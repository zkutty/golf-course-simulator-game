# Post-signing evidence preparation

This separate verifier does not change the accepted PRE_SIGNING architecture guard or unsigned desktop workflow. It hashes full supplied final-container bytes against a strict declaration and emits POST_SIGNING preparatory evidence. Declared commit, version, publisher identities and staged payload paths are not authenticated authority or extraction linkage.

Every REAL report is INCOMPLETE, certificationEligible false, and the CLI exits 2. Authenticated container-to-payload linkage, native device execution and authority producers are absent and always NOT_RUN. Payload metadata, architecture, signatures, timestamp, notarization and staple are also NOT_RUN in this first unit. No caller flags or fixture outcomes complete them. FIXTURE_ONLY is restricted to unit helpers; the CLI rejects fixture requests.

Run controls with `node --test simgolf-lite/scripts/desktop-post-signing.test.mjs simgolf-lite/scripts/desktop-post-signing-workflow.test.mjs`. The manual workflow is disabled unless the repository variable enables it, requires exact workflow-head candidate equality and a supplied artifact run ID, downloads fixed-name artifacts, and never builds, installs, signs, submits, staples or launches an application. Environment protection and supplied artifacts require independent review; an environment name is not authority. Its final job always fails INCOMPLETE, including skipped verification.

Limits: aggregate container input 1 GiB, 64 KiB streaming chunks, global synchronous hashing deadline 600 seconds checked per chunk, workflow timeout 660 seconds, exclusive report publication strictly below 1 MiB, request at most 1 MiB. Filesystem reads and fsync can block; the workflow timeout is a termination backstop, not a kernel timing guarantee. Hashes certify only bytes read at that time, not subsequent filesystem immutability. No raw verifier text, certificate private key or credential is persisted. The PowerShell adapter and metadata parsers are preparatory interfaces, not actual signature verification results.

Future distinct units must authenticate final container extraction, recursively bind all required native components, verify platform signatures and authorized publisher/timestamp policy, verify macOS notarization/staple, and produce actual native execution evidence before completion can be introduced. They require new source acceptance and real platform authority. Current signing/device gates are NOT_RUN.

Primary contracts: [SignTool verification](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool), [Get-AuthenticodeSignature](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-authenticodesignature), [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), and [GitHub environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments). Exact installed platform-tool grammar and authority remain unqualified; no platform tools were run for these fixture tests.
